# دعم العربية المقترح

[English](README.en.md) | العربية · [نظرة عامة](../../README.ar.md)

ينقل هذا الفرع النموذج العربي السابق إلى المصدر الأصلي لـ Termux تمهيداً للمراجعة. **نجحت اختبارات تحرير فعلية لـ nano 8.3 و9.1 عبر PTY، وعرض أمر عربي في htop 3.2.1**، مع إعادة تمرير المخرجات عبر محاكي Termux والرسم الأصلي في Android Canvas على API 28/34. هذه أدلة على الحالات المختبرة، وليست موافقة مشرفي المشروع أو شهادة توافق رسمية. ليس هذا إصداراً رسمياً أو تغييراً قُبل في المشروع الأصلي. راجع [مسودة طلب الدمج والأدلة](UPSTREAM_PR.md#validation) و[VALIDATION.json](VALIDATION.json) للنتائج النهائية المجمعة لاختبارات Gradle والبناء بدلاً من أعداد جولات سابقة. نتائج النموذج السابق لا تثبت سلامة هذا الفرع.

## النطاق والإعدادات الافتراضية

- **الإنجليزية هي لغة التطبيق عند البدء.** يستخدم مبدّل English/العربية لغات التطبيق في AndroidX. الترجمة تغيّر واجهة التطبيق المحيطة، لا مخرجات الصدفة أو الحزم المثبتة.
- **يتبع تدفق الطرفية إعداداً افتراضياً بحسب اللغة ما لم يُتجاوز:** العربية تفعّل التدفق افتراضياً، والإنجليزية تعطّله. عند تعطيله، بما في ذلك الوضع الإنجليزي الافتراضي، يبقى مسار الرسم الأصلي مطابقاً دون تغيير. يحتاج مسار وصل الحروف الاختياري إلى Android 6 / API 23 فأحدث؛ يحتفظ API 21/22 بمسار `drawText` الأصلي دون تغيير. هذا لا يوسّع دعم حزم المشروع للإصدارات القديمة من Android.
- تشمل الموارد العربية نصوص التطبيق ومصفوفة نصية ونصوص الواجهة المشتركة وعرض الطرفية. لا تزال التغطية تتوسع، ومنها رسائل الخدمة؛ لم تُترجم كل الرسائل الإنجليزية المكتوبة مباشرة في الشفرة أو صفحات المساعدة الخارجية. اختيار العربية لا يترجم مخرجات الصدفة والبرامج ولا يغيّر إعداد لغة الصدفة.
- عند تفعيل التدفق على API 23 فأحدث، يستخدم النص العادي في الشاشة الأساسية تدفق RTL للصف كاملاً. أما الشاشة البديلة وتتبع الفأرة ووضع مفاتيح المؤشر الخاص بالتطبيق والمحتوى الشبكي فتستخدم **حقول RTL محدودة داخل خلاياها المشغولة الأصلية**. تحفظ الصفوف المزاحة للداخل أو ذات التعداد تخطيط البرنامج المضيف أيضاً. لا يُعكس تخطيط واجهة الطرفية كاملة ولا يُنقل النص إلى الحافة اليمنى للشاشة.
- يصل Android المقاطع العربية، ويرتّب Unicode Bidi النص المختلط داخل الصف أو الحقل المعني. يبقى مخزن الطرفية وإحداثيات خلايا VT وإدخال PTY والأوامر والنص المحفوظ بالترتيب المنطقي.
- يشترك رسم المؤشر والتحديد باللمس وتعيين موضع الفأرة في خريطة محدودة تربط الخلايا المنطقية بمواضعها المرئية. لا يُعكس النص عند الإدخال أو اللصق؛ تفسيره من مسؤولية الصدفة أو المحرر المضيف.

## التحكم

1. افتح درج التنقل واضغط زر **English/العربية** الظاهر لفتح قائمة اختيار اللغة. التغيير الصريح إلى اللغة الأخرى يمسح اختيار التدفق اليدوي المحفوظ: يصبح التدفق مفعّلاً افتراضياً للعربية ومعطّلاً للإنجليزية، ما لم تتجاوزه خاصية صالحة. إعادة اختيار اللغة الحالية **لا** تمسح الاختيار اليدوي.
2. من قائمة سياق الطرفية بدّل خيار **RTL text flow and shaping** (تدفق النص من اليمين إلى اليسار ووصل الحروف) لحفظ تجاوز يدوي. يبقى الاختيار بعد إعادة تشغيل التطبيق وتدوير الشاشة، وليس مؤقتاً. وجود قيمة صريحة صالحة للخاصية يعطّل هذا المفتاح في القائمة.
3. للتجاوز عبر الملف، أضف إلى `~/.termux/termux.properties` ثم نفّذ `termux-reload-settings`:

   ```properties
   terminal-rtl-text-shaping=true
   ```

   تطلب `true` التدفق، وتفرض `false` الرسم الأصلي. لا تختار الخاصية لغة الواجهة. غياب القيمة أو عدم صلاحيتها يعني تجاهلها كتجاوز للسياسة، ولا يفرض افتراضي الإنجليزية `false` على العربية.

**ترتيب الأولوية:** الخاصية الصريحة الصالحة، ثم اختيار قائمة السياق اليدوي المحفوظ، ثم افتراضي اللغة (العربية `true` والإنجليزية `false`). احذف الخاصية وأعد تحميل الإعدادات للعودة إلى الاختيار اليدوي المحفوظ أو افتراضي اللغة. يتطلب الرسم الاختياري API 23 فأحدث؛ تختار سياسة العرض التالية بين تدفق الصف كاملاً والحقول المحدودة.

## إصلاح تراجع عرض واجهات الطرفية — 2026-09-08

يبقى وصل العربية مفعّلاً داخل الحقول النصية المكتشفة في العرض الشبكي وواجهات الطرفية. تبقى الترويسات والتذييلات وبادئات ASCII والحدود والخلايا الأخرى التي يديرها المضيف في أماكنها. يُلائم الحقل **نطاق خلاياه المشغولة الأصلية**، ولا يُمدّد أو يُحاذى إلى يمين الطرفية كلها. تبقى الرموز اللاتينية أو الرقمية السابقة للعربية بالرسم الأصلي، ومنها عمود `TIME+` في htop؛ وتظل اللاتينية والأرقام المضمّنة بعد العربية داخل الحقل جزءاً من ترتيب Bidi فيه.

تُحذف رسوم المحارف والمؤشر الأصلية التي يستبدلها الحقل المشكّل من مسار الرسم **قبل تحويلها إلى بكسلات**؛ يمنع ذلك تكرار امتدادات الحروف والآثار المتبقية، بدلاً من محاولة مسحها بعد الرسم. يحترم تعيين المؤشر والتحديد والفأرة حدود الحقل. أُصلحت معالجة الفأرة الأصلية في الخلايا العريضة للحفاظ على إحداثي البروتوكول الخام، وأصبح البحث عن الحقول بزمن خطي O(n). تبقى أسهم واجهات الطرفية ومفتاحا Home/End تحت إدارة المضيف بتسلسلاتها الأصلية.

## التوافق والحدود

| الحالة | السلوك أو القيد |
| --- | --- |
| النص العادي في الشاشة الأساسية | تدفق RTL للصف كاملاً عند تفعيله على API 23 فأحدث، دون إعادة كتابة مخزن الطرفية. |
| الشاشة البديلة أو تتبع الفأرة أو وضع مفاتيح المؤشر الخاص بالتطبيق | تُحفظ شبكة المضيف ثابتة الخلايا وتسلسلات المفاتيح الأصلية، مع وصل العربية داخل حقول محدودة بالخلايا المشغولة. لم يعد كون العرض واجهة طرفية سبباً لتعطيل الوصل. |
| الصفوف الشبكية أو المزاحة للداخل أو ذات التعداد | تُحفظ مواضع التخطيط والبادئات والحدود، ويُشكّل النص داخل الحقول المحدودة فقط. يعتمد الكشف على بنية الصف والمسافات والفواصل؛ هو استدلال لا محلّل شامل لكل عناصر الواجهة. قد لا يميّز بثقة بين عناصر مستقلة لا تفصلها إلا مسافة واحدة. |
| بادئات ASCII والأرقام والحقول المختلطة | تبقى الرموز اللاتينية والرقمية السابقة للعربية بالرسم الأصلي، بما يصلح تراجع `htop TIME+`. تظل اللاتينية والأرقام المضمّنة بعد العربية داخل الحقل خاضعة لـ Unicode Bidi. |
| nano 8.3 و9.1 | نجح تحرير فعلي عبر PTY: السهم الأيمن مرتين، ثم إدراج وDelete وBackspace وحفظ، مع التحقق من ملف UTF-8 المتوقع. نجحت أيضاً إعادة تمرير المخرجات عبر محاكي Termux وCanvas الأصلي على API 28/34. |
| htop 3.2.1 | نجح التقاط مخرجات htop الفعلية التي تعرض أمراً عربياً وإعادة تمريرها، مع حفظ الأعمدة. يثبت ذلك حالة العرض المختبرة، لا كل تفاعلات htop. |
| Claude Code CLI وCodex CLI | أعاد نموذج اختبار **اصطناعي** شبيه بلقطة الشاشة إنتاج نمط تخطيط Claude Code المبلّغ عنه، ويغطي إصلاح أسطر المتابعة المزاحة للداخل. لم تُختبر جلسة فعلية موثّقة الدخول من البداية إلى النهاية لـ Claude Code أو Codex؛ لا يُدّعى توافق رسمي. |
| الأسطر الملفوفة والنص المختلط | يُطبّق Bidi على الصف أو الحقل المرئي، لا على فقرة كاملة تمتد عبر أسطر ملتفة. قد يختلف عرض الترقيم والمسارات عن قصد كاتبها دون عزل اتجاهي. |
| السهمان الأيسر والأيمن | في الصفوف العربية ذات التدفق الكامل يرسل الأيسر غير المعدّل تقدماً منطقياً، والأيمن رجوعاً منطقياً. **ليس هذا تنقلاً بصرياً كاملاً وفق Bidi** داخل اللاتينية المضمّنة. تحتفظ واجهات الطرفية والحقول المحدودة والصفوف اللاتينية الخالصة بالأسهم الأصلية. |
| Home وEnd وBackspace والمفاتيح المعدّلة | تبقى التسلسلات الأصلية تحت إدارة البرنامج المضيف، بما في ذلك واجهات الطرفية. تعتمد الحركة الفعلية وحذف الحروف والتشكيل على الصدفة أو المحرر وإعداداته ولوحة المفاتيح أو IME. |
| الروابط الحرفية وEmoji والأجهزة | تقسيم موضع المؤشر داخل لام-ألف تقريبي. تتبع Emoji المركبة قواعد عرض خلايا الطرفية، لا هندسة عنقود المحارف كاملة. ما زال اختبار خطوط المصنّعين ولوحات المفاتيح وIME وسحب مقابض التحديد على أجهزة فعلية قيد الانتظار. |

المضيف هو من يملك شبكة واجهة الطرفية؛ محاذاة النص إلى يمين الشاشة كاملة أو عكس الواجهة يخالفان ذلك. يحفظ الوصل المحدود هذه القواعد في الحالات المغطاة، لكنه لا يستنتج حدود كل عنصر واجهة اعتباطي. عند تعثر تخطيط غير مكتشف، يبقى التعطيل اليدوي وسيلة للعودة إلى الرسم الأصلي المطابق.

## المراجعة والتحقق

### أدلة الاختبار

- **برامج فعلية:** عمل nano 8.3 و9.1 عبر PTY، وأكمل تسلسل التحرير والحفظ أعلاه وأنتج بايتات UTF-8 المتوقعة؛ وعرض htop 3.2.1 أمراً عربياً فعلياً.
- **تكامل الرسم:** أُعيد تمرير هذه المخرجات عبر محاكي Termux وAndroid Canvas الأصلي على API 28/34. تشمل حالات التراجع المغطاة الوصل المحدود ومنع رسم المحارف والمؤشر الأصليين المستبدلين وحفظ الأعمدة والبادئات وتعيين المؤشر والتحديد والفأرة.
- **دليل اصطناعي:** يغطي نموذج شبيه بلقطة Claude Code النمط المبلّغ عنه والتعداد وأسطر المتابعة المزاحة للداخل. ليس تسجيلاً لجلسة منتج موثّقة الدخول.
- **فحوص المستودع:** راجع [VALIDATION.json](VALIDATION.json) و[كتلة النتائج النهائية](UPSTREAM_PR.md#validation) للنتائج المجمعة الحالية لاختبارات Gradle وبيئة الرسم والموارد وبناء APK وتوقيعه. لا تُعِد استخدام أعداد أو بصمات جولات سابقة. أُضيف إجراء مدقّق الموارد بصلاحية قراءة فقط ونجح برنامجه محلياً؛ لا يُدّعى تشغيله على GitHub.

### إعادة التنفيذ

نفّذ من جذر المستودع؛ تستخدم بيئة اختبارات الرسم القابلة للنقل مسارات الاختبارات وبياناتها نسبةً إلى المستودع، لا إلى مساحة عمل الوكيل:

```sh
python3 app/src/test/python/validate_arabic_resources.py
./gradlew --rerun-tasks :terminal-emulator:testDebugUnitTest :terminal-view:testDebugUnitTest :app:testDebugUnitTest :app:assembleDebug
./tools/native-tests/run.sh
# بديل باستخدام Maven مباشرة:
mvn -f tools/native-tests/pom.xml test
```

### ما بقي للتحقق على الأجهزة أو خارج الحالات المغطاة

- مبدّل اللغة بالاتجاهين مع جلسات PTY حيّة وإعادة التشغيل والتدوير والترقية الفعلية للنظام وثبات إعدادات اللغة والخاصية على أجهزة؛ لا تستبدلها اختبارات السياسة والترحيل الآلية.
- خطوط المصنّعين ولوحات المفاتيح وIME ولوحة مفاتيح فعلية ووميض المؤشر وسحب مقابض التحديد والنسخ واللصق وحذف التشكيل بواسطة المضيف على الأجهزة.
- تخطيطات إضافية لواجهات الطرفية، خصوصاً العناصر المستقلة التي تفصلها مسافة واحدة، والاستخدام الفعلي الموثّق الدخول لـ Claude Code/Codex من البداية إلى النهاية.

عند الإبلاغ، اذكر معرّف الالتزام وإصدار Android/API والخط ولوحة المفاتيح وإعداد التدفق والبرنامج المضيف وخطوات إعادة إنتاج مختصرة. احذف محتويات الطرفية الخاصة وبيانات الدخول من السجلات والصور. اتبع [دليل التصحيح الأصلي](../../README.md#debugging).

## سلامة نشر الفرع

**عطّل GitHub Actions في أي فرع GitHub جديد قبل نشر الإصدارات.** إجراء إرفاق APK الموروث قد يحذف الإصدار ووسمه عند الفشل، وإجراء JitPack يستهدف المستودع الرسمي. احفظ إجراءات المشروع الأصلي في الرقعة الأساسية وراجع أتمتة نشر الفرع بصورة منفصلة؛ راجع [تفاصيل الإجراءات](UPSTREAM_PR.md#fork-publication-safety). أُضيف إجراء CI منفصل للتحقق من الترجمة؛ نجح برنامجه محلياً ولم يُشغّل على GitHub بعد.
